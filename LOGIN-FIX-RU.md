# Clean 2 — Google-вход и сохранение почтового входа

Результат: `output/TikTok_Clean_47.1.4_Universal.apk`, versionCode **2024701041**, прежняя подпись Clean. Новый APK устанавливается поверх Clean 1 без удаления приложения. Имя версии TikTok оставлено 47.1.4, чтобы не менять его формат в запросах приложения.

## Что обнаружено

Сравнены Google-провайдеры оригинала, Central, Platinum и Private Plus. Они содержат нативный Google-вход и отдельный штатный браузерный провайдер `google_web`. У Central, Platinum и оригинала совпадают Google client ID и URI возврата браузерного провайдера. В оригинале выбор `X.1EAt.LJFF` предпочитал нативный Google-провайдер, если Google Play Services доступны. Доступность Play Services сама по себе не подтверждает пригодность подписи конкретного APK для OAuth.

Подпись нашего APK отличается от оригинала. Для Android Google Sign-In учитывается SHA-1 сертификата приложения: [документация Google](https://developers.google.com/android/guides/client-auth). Это вероятная причина описанного отказа Google-входа, но точный код ошибки с телефона не получен. Успешный вход в исходный мод неделю назад подтверждён пользователем; текущая авторизация этим аккаунтом в лабораторном окружении не выполнялась.

## Исправление

Для Google включён существующий браузерный OAuth-провайдер TikTok. Алиас `google_onetap`, который мог отправить вход в Credential Manager до выбора браузерного провайдера, нормализуется в обычный Google-маршрут. Сохранены штатные Google client ID, HTTPS-адреса, обмен OAuth-кода, обработчик возврата в приложение, проверки ответа и создание сессии TikTok. Нового сайта для ввода пароля нет.

Вход по почте/имени пользователя, паролю, коду и восстановление доступа остаются штатными. Нормализация меняет только Google-алиасы; параметры почты, признак «вход/регистрация», остальные провайдеры и passkey не меняются. DEX с `EmailLoginFragment` (`classes22.dex`) и отдельно проверенные неизменённые DEX SDK (`classes34.dex`, `classes36.dex`) побайтно совпадают с оригиналом. Отдельная проверка в Android подтверждает сохранение параметров почтового входа. Это не подтверждение успешного серверного входа по произвольной почте.

## Проверка

- 45 JVM-проверок: предыдущие 33 плюс 12 случаев маршрутизации Google и сохранения остальных способов входа.
- 31 Android-проверка на установленном APK: предыдущие функции, реальный `X.1EAt.LJFF`, Google/OneTap/web-алиасы, неизменённые Facebook/Line, отображение браузерного провайдера в Google backend, параметры Google/email/passkey, разрешение callback URI, наличие браузера и новый versionCode.
- Публичный Google OAuth-адрес проверен анонимно с PKCE: получена страница `accounts.google.com/v3/signin/identifier`, HTTP 200, без выявленных маркеров `invalid_client`, `redirect_uri_mismatch`, `invalid_request`. Учётные данные не вводились, вход не завершался.
- APK проверяется на подпись, целостность, ZIP-выравнивание 16 КБ, сохранение исходных классов, отсутствие тестовых классов и изменение только запланированных файлов. Установка поверх предыдущей сборки в отдельном Android 16 эмуляторе прошла успешно.

Android-проверки маршрутов выполняются с обычным `Application` тестового окружения, поскольку TikTok заменяет instrumentation при штатном старте. Штатный холодный запуск проверяется отдельно. Настоящий вход Google и вход по почте требуют проверки на телефоне с соответствующим аккаунтом; их успешное завершение пока не подтверждено.

## Как проверить на телефоне

Установите этот выпуск поверх текущего Clean. Откройте **«Войти» → «Продолжить с Google»**, выберите Google-аккаунт, связанный с нужным TikTok, и завершите вход в браузере. Штатный callback возвращает в TikTok.

Для друзей доступны прежние поля входа по почте/имени пользователя и паролю/коду. Для восстановления предусмотрен штатный экран: [официальная справка TikTok](https://support.tiktok.com/en/log-in-troubleshoot/log-in/the-way-i-logged-in-last-time-is-no-longer-available). Сообщение сервера об отсутствии конкретной привязки аккаунта не заменяется фиктивным успешным входом.

Исходники исправления: `src/mod/clean/AuthRouting.java`, `scripts/patch_auth_routing.py`, `scripts/axml_version.py`. Полный предыдущий выпуск сохранён локально в `analysis/previous-builds/clean1`, ключ подписи прежний. APK не публиковался, источник обновлений по-прежнему не настроен.
