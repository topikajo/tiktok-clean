# TikTok Clean — тестовая персональная сборка

Основной APK: `output/TikTok_Clean_47.1.4_Universal.apk`. Текущий выпуск — Clean 2, versionCode 2024701041, с исправлением маршрута Google-входа. Он собран на проверенном оригинале 47.1.4, сохраняет штатные красные/розово-красные лайки и современные компоненты оригинального приложения. Это версия для проверки на телефоне, а не подтверждение работы всех возможностей с сервером TikTok.

Google-вход использует существующий браузерный OAuth TikTok и возвращается в приложение. Вход по почте/имени пользователя, паролю, одноразовому коду и восстановление доступа сохранены. Выпуск устанавливается поверх предыдущего Clean 1 с той же подписью. Разбор исправления и ограничения проверки: [LOGIN-FIX-RU.md](LOGIN-FIX-RU.md).

Подробный разбор пяти исходных модов, изменения и границы проверки: [AUDIT-RU.md](AUDIT-RU.md). Хеши результатов: [release/SHA256SUMS.txt](release/SHA256SUMS.txt).

## Основной вариант

- ARM64 и ARMv7, Android 6.0 и новее. ARM64-библиотеки оригинала имеют выравнивание для страниц памяти 16 КБ. Pixel и Poco физически не проверялись.
- Из выдаваемого списка ленты отфильтровываются записи, которые сам TikTok помечает рекламой.
- Включены существующие клиентские флаги стикеров в комментариях. Доступность и успешная публикация также зависят от аккаунта и сервера.
- В личном чате добавляются кнопки «🔥 Автоогонёк» и «Правка / удаление». Автоотправка включается отдельно для каждого чата и аккаунта. При отсутствии собственных сообщений около 20 часов мод пробует отправить 🔥 через обычный механизм TikTok.
- Правка и скрытие — экспериментальная синхронизация отображения между двумя пользователями этой сборки. Оба должны включить режим в чате. Исходное сообщение остаётся на сервере.
- Вверху настроек добавляется строка проверки обновлений. Доступны HTTPS-зеркала, повторная загрузка с сохранённого места при поддержке HTTP Range, проверка SHA-256 и подписи APK, затем обычная установка Android.

В этой сборке источник обновлений пока пуст. Когда будет подготовлен и опубликован первый выпуск, адрес его JSON можно указать долгим нажатием на строку обновления. Ничего не опубликовано на GitHub или стороннем хостинге.

## Первая установка

Все APK используют пакет `com.zhiliaoapp.musically`; одновременно установить их как разные приложения нельзя. Подпись этой сборки отличается от подписи оригинала и скачанных модов. Android может потребовать сначала удалить прежний TikTok. Сохраните локальные черновики перед удалением: они могут пропасть вместе с данными приложения. Удалять доверенные сертификаты телефона не требуется.

После входа откройте нужный личный чат. Для правки/скрытия включите режим мода у обоих участников, обменяйтесь запросами подключения и прокрутите чат до собственного текстового сообщения. Для автоогонька включите кнопку только в нужных чатах. Если оба включили режим мода, можно скрывать помеченные автоматические 🔥 в интерфейсе этой сборки; на сервере сообщения сохраняются.

Android может задерживать фоновую работу и не выполняет её после принудительной остановки приложения. После перезагрузки откройте приложение для запуска планировщика. Активность второго участника также нужна для серии. Полностью невидимое продление без обмена сообщениями не реализовано.

## Исходники и повторная сборка

Нужны Python, JDK 17 или новее, Android SDK build-tools 36.1.0, android-36.1/android.jar и JADX 1.5.6. `JAVA_HOME` должен указывать на JDK; Java 8 из PATH здесь не подходит. Исходные APK должны совпадать с закреплёнными SHA-256 в `scripts/build_clean.py`.

Для текущего подготовленного рабочего каталога:

```powershell
python scripts/compile_hooks.py
python scripts/build_clean.py build
python scripts/verify_output_classes.py
```

Для подготовки патчей в свежем каталоге после размещения исходных APK в `others` и `originals` и инструментов в `tools`:

```powershell
& "$env:JAVA_HOME/bin/javac.exe" -cp "tools/jadx/lib/jadx-1.5.6-all.jar" -d tools scripts/DexTool.java scripts/SourceTool.java
python scripts/audit_apks.py
python scripts/audit_apks.py originals/TikTok_47.1.4_original_apkpure.apk
python scripts/compile_hooks.py
python scripts/build_clean.py prepare --region belarus
python scripts/extend_patches.py
python scripts/patch_auth_routing.py
python scripts/prepare_manifest.py
python scripts/build_clean.py build
python scripts/verify_output_classes.py
```

`prepare` не перезаписывает существующие каталоги патчей. Для текущего рабочего каталога используйте уже подготовленные патчи в `patches`, а не повторную подготовку поверх них.

Для последующих обновлений нужно сохранять один и тот же локальный ключ подписи `tools/signing/local-clean.jks`. Ключ и файл пароля исключены из Git и не должны попадать в публичный репозиторий. Формат выпуска — `release/update-template.json`; его заполнение и публикация будут отдельной работой.
